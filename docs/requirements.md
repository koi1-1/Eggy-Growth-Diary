# 开发需求

> 项目：知乎黑客松 2026「校园新锐季」参赛作品 ——「蛋养学习」游戏
> 一句话：把知乎用户的「收藏」变成「学习」的游戏化学习工具，对抗「收藏即遗忘」。

## 1. 项目背景

- 目标用户：知乎上收藏了大量内容却从不回看的用户（学生、备考、自我提升人群）
- 核心痛点：收藏即遗忘——收藏动作与回顾动作脱节，学了就忘、找不到、没吸收
- 产品思路：把用户收藏用 AI 聚类成「蛋」（兴趣/知识主题），领养蛋后通过学课程、复习赚资源「喂蛋成长」，用养成游戏驱动学习

## 2. 核心玩法（学习赚金币，金币换资源，喂蛋成长）

**统一为一条资源链路**（只有一个产出源：学习）：

```
学课程   → 得金币
复习测验 → 得金币
        ↓
   金币兑换 ──→ 🍎 苹果（10 金币）/ 💧 水滴（5 金币）
        ↓
苹果喂食 / 水滴喂水 → 蛋成长值↑ → 成长值满 → 蛋升级
换装     → 给蛋换外观
徽章     → 完成学习/养成里程碑解锁（MVP 先占位）
```

- **金币**：唯一的产出资源，学课程 / 复习测验获得；显示在**养蛋页顶栏右上角**（含等级与兑换入口）
  - 金币即原「经验值」——同一种东西，改名为金币并赋予购买力
- **苹果 / 水滴**：喂养资源，**用金币兑换得到**，不再由学习直接掉落
  - 苹果喂食 +15 成长值；水滴喂水 +10 成长值
- **兑换比率**（MVP 默认值，可调）：苹果 10 金币 / 水滴 5 金币
- **产出数值**（MVP 默认值，可调）：学完课程 +30 金币；复习每答对 1 题 +10 金币
- 换装：给蛋换外观（MVP 先做 1-2 个）

> 设计意图：用户只需理解「学习 → 金币 → 喂蛋」一条链路，降低认知负担。

### 2.1 数值权威与已评审的外部方案

- **数值由后端唯一决定**（常量集中在 `server/routes/eggs.js`），前端只做展示与触发动作；接口不接受客户端上传的金币/成长值，防止篡改
- **已评审 `design/精力值相关(1).docx`（《蛋宝成长记》规则调整版），MVP 不采纳**，理由与保留项：
  - 该方案把「苹果/水滴」改为 7 种具名食物、金币:成长 = 1:1、总成长 1200 分三阶段（破壳/幼体/成长体/成熟体），并新增心情值、消化倒计时、每日上限与防刷标记。范围过大，与 9/15 截止时间冲突
  - 其中「课程点赞 +5 / 评论 +10 金币」**无法实现**：知乎开放平台用户侧接口全部为只读（collections / contents / favlists / followees / question_recommendations），没有点赞、评论写接口
  - **MVP 保留**：苹果（10 金币 / +15 成长）、水滴（5 金币 / +10 成长）、学完课程 +30 金币、复习每答对 +10 金币、成长 0–100 满级 → 等级 +1
  - 该文档留作后续版本（内容更丰富、含时间与防刷机制）的设计输入，不在本次提交范围内

## 3. 页面结构（6 个页面，像素风）

> 视觉为**原创像素/复古游戏风**（参考 `design/6.png`、`design/7.png`），全部由纯 CSS + 内联 SVG 手作，不使用任何外部图片/webfont。规范见 `docs/design.md`。

| 层级 | 页面 | 内容 |
|---|---|---|
| 开屏 | EARTH ONLINE | 像素标题 + 「ENTER」按钮进入；同会话只出现一次 |
| 一级 | 蛋气泡墙 | 登录后，基于用户收藏 AI 聚类成若干「主题蛋」展示；无收藏时显示推荐主题蛋 |
| 二级 | 领养成功 | 点击气泡后弹出「【恭喜您领养成功！】」像素弹窗 |
| 三级 | 蛋的知识点主页 | 顶栏「我的宠物」+ 右上角金币（金币数 + 等级 + 兑换入口）+ 蛋展示 + 右侧竖排苹果/水滴喂水/换装；下方「今天要做什么？」4 个像素气泡卡：课程 / 复习 / 徽章 / 探索 |
| 四级 | 课程详情页 | AI 整理的 **0→1 课程**：一句话排课原则 + **6 张课卡网格** + 参考来源 |
| 四级·单节 | 单节课详情页 | 点课卡进入：本节目标 / 为什么排这里 / 学习文章（带「为什么选它」）/ 行动任务，底部可切上一节·下一节 |
| 五级 | 复习测验页 | 自测问答，巩固已学 |

## 4. 蛋与课程的衔接

```
用户登录(OAuth) → 读收藏(标题+摘要) → AI 聚类成 N 个主题蛋(3~6个)
   → 用户领养蛋 → 蛋主页
       ├─ 课程：knowledge search(蛋主题) → AI 整理成 6 节课的 0→1 课程 → 课卡网格 → 单节课详情
       ├─ 复习：AI 基于课程生成自测题 → 复习测验页
       └─ 养成：学/复习得金币 → 兑换苹果/水滴 → 喂蛋 → 成长/升级/换装/徽章
```

- 蛋的主题来自「用户收藏」→ 保证个性化
- 课程内容来自「知乎直答公共知识库」→ 保证有优质全文
- 两者通过「蛋主题 → 检索 query」衔接

## 5. 课程内容：来自知乎直答公共知识库

数据源为公共知识库 RAG 检索，覆盖任意主题、含完整正文：

```
GET /api/v1/knowledge/search  --query <蛋主题> --scope public --limit N
```

每条返回 `DocName`（标题）+ `Content`（正文片段）+ `OriginUrl`（原文链接）+ `KnowledgeBaseID`。

课程生成分三步（都在后端）：
1. **检索**：按蛋主题检索知识库，得到相关优质内容片段
2. **整理**：AI 把片段**整理成一份 6 节课的 0→1 课程**（不是罗列原文，也不是平铺知识点）
3. **课程详情页**：先看到 6 张课卡组成的课程总览，点进任一课卡看该节课的正文；原文链接作为「参考来源」附在总览页末

### 5.0 课程形态：6 节课的 0→1 课程

课程不是「概述 + 知识点分节」的平铺结构，而是**按学习顺序排出的 6 节课**——一节一节学下去，就能从零走到能动手。形态取自 `design/学习计划_通用模板.md`：

```
课程总览页
├─ 标题 + 一句话排课原则
├─ 课卡网格：Lesson1(整行大卡) / Lesson2 + Lesson3 / Lesson4(整行大卡) / Lesson5 + Lesson6
└─ 参考来源（长期有效的原文链接）

单节课详情页（点课卡进入）
└─ 本题目标 / 为什么排在这里 / 学习文章(1~2 篇，每篇附「为什么选它」) / 行动任务(2~3 个，可勾选)
   底部：上一节 · 下一节
```

排课同时满足**三个维度**：

1. **认知深度递进**：从「知道是什么」到「能动手做」，前面的课是后面的课的基础
2. **行动门槛递进**：越靠前行动成本越低——先纯阅读认知，再动手实践，最后持续投入
3. **主题匹配**：每节课安排的文章，其内容主题要与该节课目标一致，并由 AI 给出「选它的理由」

- 每颗蛋对应「**一门 6 节课的课程**」；节数固定为 6（课卡网格按 6 张排），素材不够时后几节没有文章，但仍有目标与理由
- 复习 = AI 基于课程生成自测题（选择题）；复习卡片与艾宾浩斯节奏（+1/+3/+7/+21 天）、进度追踪表**后置到 Step 5.2**
- 课程生成是「检索 → 整理 → 出题」的**固定流水线（后端函数）**，输入蛋主题当参数即可，**无需多步自主 Agent**
- **养成数值仍是课程级**：「学完了」按钮在课程总览页，一门课一次性 +30 金币，不按节计费

### 5.1 素材来源与降级（已实现）

| 优先级 | 素材来源 | 前置条件 | 落到课程里的「参考来源」 |
|---|---|---|---|
| 1（主） | 知识库 RAG 检索公开知识库正文片段 | 需 `ZHIHU_ACCESS_SECRET` | `DocName` + `OriginUrl` |
| 2（降级） | 用户自己的收藏（标题 + 摘要 + URL） | 无（有收藏即可） | 收藏标题 + 原文 URL |

- 降级自动发生：未配置 Access Secret、或检索无结果时，改用收藏做素材，**链路不中断**
- **两条路径的「参考来源」都只取自素材本身，不允许模型编造 URL**；课程注明来源，不宣称原创
- **参考来源只收长期有效的链接**：知识库里的 PDF/EPUB/MD 文档给的是带签名的下载直链（`assets*.zhihu.com`，URL 内含过期时间，实测约 1 小时后失效）。这类素材照常参与课程正文，但**不作为引用链接**展示——给用户一个必然失效的链接比不给更糟。只有知乎站内内容页（`www/zhuanlan.zhihu.com`）才作为参考来源
- 同一份文档常被多个片段分别召回（实测一份 EPUB 一次返回 3 条），按标题去重后再做素材，避免课程重复讲同一份材料
- 检索额度 500 次/天，因此课程按「用户 + 蛋」缓存，同一颗蛋只生成一次

#### 5.1.1 筛选依据：不做「赞同×1 + 评论×2」加权

`design/学习计划_通用模板.md` 用「赞同数 ×1 + 评论数 ×2」给候选文章加权排序。**本项目不采用该筛选**：

- 知识库检索接口（`POST /api/v1/knowledge/search`）的返回字段只有 `Content[]`（正文片段）、`DocName`、`OriginUrl`、`KnowledgeBaseID`、`RecallContentID`，**没有任何赞同/评论/收藏数**
- 用户侧接口全部只读且不返回互动数，无法从别处补齐
- 既然拿不到这个数据，就**不基于它做筛选**，也不拿别的指标假装是它

**替代方案**：沿用知识库检索自身的相关性排序，由 AI 依据「内容主题与本阶段目标的匹配度」把素材分配到各阶段，并给出「选它的理由」（`articles[].why`）。理由说的是内容讲了什么、为什么适合这个阶段，不是热度。

> 数据来源的诚实标注：课程详情页页脚的来源标签如实显示「来自知乎知识库」或「来自你的收藏」，不夸大。

## 6. 边界问题（已确认）

| 边界 | 决策 |
|---|---|
| 冷启动（无收藏/很少） | 展示系统「推荐热门主题蛋」+ 提示「去知乎多收藏，蛋会更多」 |
| 蛋的负反馈 | 纯正向：不喂也不会死/退化，只暂停成长 |
| 蛋数量上限 | 不设上限，自由收集；重复领养提示「已领养过」 |
| 数据持久化 | 后端接数据库，蛋/金币/苹果/水滴/进度刷新后不丢 |
| 金币不够兑换 | 提示「金币不够，去学课程赚金币」，不做负向惩罚 |
| 检索/生成失败兜底 | 换关键词重试一次 → 仍无果则提示「该主题暂无课程」；额度耗尽/失败给真实降级提示，不伪造内容 |
| 学习进度 | MVP 记「课程是否完成」+「复习答对几题」，间隔重复后置 |
| 隐私版权 | 收藏数据仅当场用于生成、不长期存储；课程保留原文来源、不宣称原创 |

## 7. MVP 范围（最小闭环）

- **必做**：登录 → 读收藏 → AI 聚类生成蛋 → 蛋墙 → 领养 → 蛋主页 → 课程（系统知识）→ 复习自测（简版）
- **后置/加分**：复杂换装、蛋多阶段孵化、徽章墙、探索领域推荐、多门课拆分
